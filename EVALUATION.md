# Evaluation

This document measures the engine against the ground truth in `sample_submissions/dataset_manifest.json`, analyses its failures honestly, and explains the model and index trade-offs. All numbers in the *Results* section are generated by one command and can be reproduced:

```bash
python scripts/evaluate.py        # writes evaluation/results.json and refreshes the Results section below
pytest                            # 42 unit / integration / edge-case tests
```

## 1. What is evaluated and how

**Dataset** (details in the manifest): 15 files (7 PDF, 5 DOCX, 3 MP4) with planted relationships:

| Ground truth | Files | Purpose |
|---|---|---|
| Exact copy (cross-format) | `submission_01.pdf` → `submission_02.docx` | verbatim detection |
| Paraphrase (Scenario 2) | `submission_03.docx` ↔ `submission_04.docx` | semantic detection with low lexical overlap |
| Cross-modal (Scenario 1) | `submission_05.pdf` (p. 2) read in `pitch_01.mp4` (3.0–23.4 s) | ASR + page/timestamp localisation |
| External copy | `submission_09.pdf` (2 verbatim Wikipedia paragraphs + 1 edited sentence), `pitch_02.mp4` (spoken Wikipedia definition) | external engine, incl. speech |
| Shared 150-word prompt + references (Scenario 4) | 01, 02, 03, 05, 11 | must **not** be flagged |
| LLM-generated | `submission_06.pdf` | AI detection |
| Independent originals | 07 (same case: hard negative), 08 (other case), 10 (heavily formatted), 11 | false-positive control |
| Degraded (Scenario 3) | `submission_12.pdf` (0 bytes), `pitch_03.mp4` (no audio track) | robustness |

**Units of evaluation**

* **Pair level:** every unordered pair of the 13 analysable files (78 pairs). A pair is *predicted positive* when at least one passage is reported between the two files. There are 3 true positives and 75 true negatives. This is the main measure of the peer and cross-modal engine.
* **Document level:** copying involvement (peer or external ≥ 10 %), external copying, AI-generated (≥ 60 %), and overall risk ≥ MEDIUM.
* **Scenario checks:** each brief scenario is verified programmatically, including the exact page and time window for Scenario 1.
* **AI-detector benchmark:** 26 genuinely human paragraphs (Wikipedia revisions saved before ChatGPT existed) vs 28 LLM paragraphs on the same 14 topics, with leave-one-out cross-validation.
* **Sweeps and ablations:** each component is switched off in turn, plus a lexical-only baseline, all on the same extracted documents. ASR runs once.

## 2. Reading the results

* **The three planted copy relationships are all found, and none of the 75 independent pairs is flagged.** That includes the hard negative `submission_07` (same case, same vocabulary, written independently) and the AI-generated answer, which is generic and topically close to everything.
* **Recall depth matters as much as recall.** The paraphrase pair is recovered at 81 % of its assessed words (11 of 13 sentences, each paraphrased). The cross-modal pair is recovered at 87 %: the spoken intro "Hello, here is our pitch…" is correctly *not* matched. The external copies are recovered at 52 % (`submission_09`, which is half original) and 86 % (`pitch_02`).
* **Each component earns its place** (ablations):
  * Without boilerplate detection, precision falls to **0.25**: the shared prompt alone links all 5 template files.
  * Without chunk-context matching, the paraphrase pair is **missed**. The lexical-only baseline misses it too. This is exactly the failure of "traditional word-matching tools" that the brief describes.
  * The chunk-context threshold has a clear safe band. At 0.75 there are 2 false pairs, 0.80–0.85 is clean, and at 0.90 the paraphrase is lost. The default of 0.85 sits inside the band.
  * Pair-level results are **flat across sentence thresholds 0.75–0.95**. The evidence-strength filter makes the engine insensitive to this choice, which is the robustness wanted from a threshold nobody can tune per challenge. The row "No evidence filter + sentence threshold 0.80" shows what the filter prevents.
  * The lexical rescue and merge window do not change pair-level numbers here. They fix **attribution**: without them, `pitch_02`'s first sentence and `submission_09`'s merged "Gross margin" sentence were credited to the wrong source sentence (failures F3/F4 below).
* **AI detection:** the RoBERTa classifier carries almost all the signal (AUC 0.955). Perplexity (0.76) and burstiness (0.65) are weak on their own, and the fitted weights give them almost nothing. On this benchmark the calibrated combination does **not** beat the classifier at ranking (LOO AUC 0.941 vs 0.955, the same accuracy). It is kept because it turns the classifier's saturated 0.999/0.001 outputs into graded probabilities, and because the perplexity features remain an independent check if a future model fools the classifier. On the submissions, the LLM-written `submission_06` scores **93 %**; human-style files score 4–17 %.

## 3. Failure analysis

These are real failures observed while building and evaluating the engine. Each records the symptom, the root cause, what was changed, and what remains.

### F1. False peer match caused by PDF line-wrapping (fixed)

* **Symptom.** `submission_05.pdf` was reported as copying *"with clear milestones, key risks and the metrics the board should track."* from `submission_01.pdf`. That sentence is part of the shared case prompt, which should have been discounted.
* **Root cause.** When paragraphs were rebuilt from PDF lines, the full-width line *"demanded deeper discounts, and two venture-funded direct-to-consumer brands entered its core"* has only 11 "words", because hyphenated compounds count once, and no punctuation, so it was classified as a heading. That split the prompt into fragments. One fragment appeared only in the two PDFs (DOCX files keep paragraphs intact), so it fell below the 3-file boilerplate rule and became "evidence".
* **Fix.** A line can only be a heading or table row if it is also visually short (under 75 % of the page's 90th-percentile line length). A second bug followed from this: the median line length was a poor estimate on table-heavy pages, so the percentile is used. Regression test: `test_full_width_line_with_few_hyphenated_words_is_not_a_heading`.
* **Lesson.** Boilerplate detection is only as good as segmentation. Format-specific extraction differences can turn template text into evidence.

### F2. Same-topic false positives at the initial thresholds (fixed by calibration; residual risk remains)

* **Symptom.** With the first thresholds (sentence 0.80, chunk 0.75, sentence-in-chunk 0.65), six independent pairs were flagged. Examples: the AI answer `submission_06` vs `submission_04` on *"Several interconnected factors have contributed to the decline in Kestrel's gross margin"* ↔ *"The decline in Kestrel's gross margin stems largely from the way it sources raw materials"* (cosine **0.836**), and `submission_05` vs `submission_02` through a loose context match (0.70).
* **Root cause.** This is the brief's "false positive on common jargon". Independent answers to the same case share topic sentences. Measured distributions: the best single-sentence cosine is **0.887** for the true paraphrase pair but already **0.836** for an independent pair, so the two overlap. The best *chunk* cosine is **0.893** vs at most **0.809**, so the two separate.
* **Fix.** Data-driven re-calibration: sentence 0.85, chunk gate 0.85, sentence-in-chunk 0.60. An evidence-strength rule was added: an isolated single-sentence semantic match needs cosine ≥ 0.90 or near-verbatim wording. Precision went from 0.33 to 1.00 with recall unchanged ("Old defaults" row).
* **Residual risk.** The margin between the paraphrase pair (0.893) and the closest independent pair (0.809) is only about 0.08 on this dataset. A heavier paraphrase, or two teams arguing the same niche recommendation, could cross it. **Resolution path:** calibrate per challenge on a small labelled sample, add a cross-encoder re-ranker (e.g. `cross-encoder/stsb-roberta-base`) on candidate pairs, and route the 0.80–0.85 band to human review instead of auto-flagging.

### F3. Correct match, wrong source sentence: cosine-only counterpart choice (fixed)

* **Symptom.** `pitch_02.mp4` reads two consecutive Wikipedia sentences, but only one was reported (external 46 % instead of 86 %).
* **Root cause.** For the first spoken sentence, the top cosine hit (**0.889**) was a *different* definition sentence in the same article, with lexical similarity 0.28. The sentence actually read aloud scored cosine **0.851** but Levenshtein **0.79**. Keeping the max-cosine counterpart broke the passage in two, and the evidence filter then dropped the fragment.
* **Fix.** Among qualifying sentences of one target document, keep the one with the highest **cosine + Levenshtein**. Sentences with cosine 0.70–0.85 are also accepted when Levenshtein ≥ 0.70 (the lexical rescue).
* **Lesson.** Semantic similarity answers "says the same thing". Plagiarism evidence needs "is the same text", so the two signals are complementary.

### F4. A merged sentence attributed to the wrong paragraph (fixed)

* **Symptom.** `submission_09`'s *"Gross margin is the difference between revenue and the cost of goods sold, divided by revenue, and it is always expressed as a percentage."* was cited against paragraph **2** of the Wikipedia article (a sentence with lexical similarity 0.38).
* **Root cause.** The student merged two source sentences into one. Compared one-to-one, neither source sentence passes (cosine 0.83 / Levenshtein 0.62 and cosine 0.88 / Levenshtein 0.30).
* **Fix.** A **merge window**: each candidate is also compared with itself plus its neighbour. Here the window reaches Levenshtein **0.83**, both sentences are cited, and the match is correctly classed as *near-verbatim* from paragraph 1.

### F5. ASR normalisation lowers lexical evidence (ambiguous; not fixed)

* **Symptom.** In `pitch_01.mp4`, Whisper writes *"300 rupees"* where the PDF says *"three hundred rupees"*. In `pitch_02.mp4` it writes *"fulfillment"* (US spelling) where the source has *"fulfilment"*. Both copies are still caught (cosine 0.99 and 0.92), but `pitch_02` is classed *near-verbatim* rather than *verbatim*, and Levenshtein drops a few points.
* **Why it matters.** With real student recordings (accents, noise, mumbled numbers) the drop will be larger. TTS audio is cleaner than real speech, so **these results overstate ASR accuracy**.
* **Resolution path.** Normalise numbers in both texts before lexical scoring (`num2words` / inverse text normalisation) and fold spelling variants. Use Whisper `small` for flagged files. Evaluate on real recorded pitches, including accented English, before trusting the timestamps' lexical labels.

### F6. The source file is flagged too (by design, but ambiguous for reviewers)

* `submission_05.pdf`, the *victim* whose paragraph was read in `pitch_01`, receives MEDIUM risk (22.7 %). Content similarity is symmetric; it cannot say who copied whom. The report says so explicitly, and a reviewer can see the match is to a video recorded later. **Resolution:** use upload timestamps and authorship history to label the likely source, and down-weight the earliest submitter.

### F7. Limits of the AI-detection evaluation (honest caveats)

* The "human-style" submissions were drafted with AI assistance to emulate student writing (see the manifest's provenance note), so the 11/11 correct AI decisions on submissions are **weak evidence**. The benchmark with genuinely human pre-2022 text is the meaningful measurement.
* On that benchmark the detector makes 2 false positives and 3 false negatives out of 54. One AI paragraph (`ai_28`, on psychological pricing) scored only 0.115 from the classifier.
* The AI benchmark texts were written by a single LLM and both classes are in encyclopedic style. Other LLMs, student essays, and text that was AI-drafted and then human-edited will be harder. Detectors are documented to be biased against non-native English writers (Liang et al., 2023, *GPT detectors are biased against non-native English writers*).
* Short texts and transcripts are therefore reported as `INSUFFICIENT_TEXT` or low-confidence, and a low-confidence AI score can never push a file to HIGH.

## 4. Trade-off analysis

### Embedding model

| Model | Params / dim | CPU speed (relative) | Notes |
|---|---|---|---|
| **all-MiniLM-L6-v2** (chosen) | 22 M / 384 | 1× (fastest) | Trained for semantic similarity on 1 B+ sentence pairs; strong on paraphrase; 256-token window |
| all-mpnet-base-v2 | 110 M / 768 | ≈ 4–5× slower | Typically a few points better on STS benchmarks; 2× the vector memory |
| bge-small / e5-small | 33 M / 384 | ≈ 1.5× slower | Retrieval-oriented; comparable size |
| paraphrase-multilingual-MiniLM-L12-v2 | 118 M / 384 | ≈ 3× slower | Needed if submissions are not English |

MiniLM was chosen because the brief targets commodity CPUs. The measured margins on this task are adequate (exact 1.00, cross-modal 0.99–1.00, paraphrase chunk 0.89 vs non-copy ≤ 0.81). The 384-d vectors also halve index memory at scale (§6.2 of the README). Its weakness is the narrow paraphrase margin (F2). The first upgrade would be a **cross-encoder re-ranker on candidate pairs only**, rather than a bigger bi-encoder for every sentence. That costs one extra model call per *candidate*, not per sentence.

### Granularity: sentences + chunks

Sentence-level vectors give precise evidence and percentages. Chunk-level vectors (~200 tokens) capture argument-level similarity, which is what reveals paraphrase. Using both costs roughly 1.1× the embeddings of sentences alone, which is cheap.

### Vector index

Exact `IndexFlatIP` is used: with about 300 submission sentences and about 1,900 reference sentences, brute force is instant and exact, so recall loss from approximate search is impossible to confuse with model error. The HNSW path is implemented (`VectorIndex(kind="hnsw")`, tested to return the same nearest neighbours) for the 10,000-file setting, where it provides sub-millisecond queries for about 0.2 GB of graph overhead.

### ASR model

Whisper `base` with int8 on CPU transcribes the 26-second clips in a few seconds with correct word timing (ground-truth window recovered to 100 %). `tiny` is about 2× faster but makes more errors on numbers and names. `small` is about 3× slower and is the recommendation for real, accented recordings (F5).

### AI detector

A fine-tuned classifier is accurate in-domain but brittle under distribution shift. Perplexity features are model-agnostic but weak. Combining them with a calibrated logistic regression costs about 0.5 GB of extra model weights and about 1 s per document on CPU, and gives interpretable signals (each report lists all three). Paid detectors were excluded by the brief.

## 5. Threats to validity

1. **Thresholds were calibrated on the same small dataset they are evaluated on.** With only 3 positive pairs, a perfect score cannot be generalised. The sweep shows a *plateau* (chunk threshold 0.80–0.85 and sentence threshold 0.75–0.95 all give identical results) rather than a single lucky value, which reduces the overfitting risk. A proper estimate needs a held-out set of real submissions.
2. **Synthetic data is cleaner than reality:** TTS speech, consistent formatting, and paraphrases written deliberately to be paraphrases.
3. **The AI-detection ground truth on submissions is confounded** (F7).

The 95 % Wilson interval for a 3/3 recall is roughly [0.44, 1.0]. The numbers above demonstrate that the mechanisms work as designed on every planted case; they are not population estimates.

## 6. Tests

`pytest` runs 42 tests in about 30 s (CPU). They cover:

* normalisation (ligatures, hyphenation, control characters);
* header/footer removal, including the safety valve;
* sentence splitting and citation detection;
* chunk budget and overlap;
* inner product = cosine, and document-level self-exclusion;
* range-search tie handling, and HNSW vs Flat agreement;
* the boilerplate rule and how its threshold scales with corpus size;
* lexical metrics, coverage maths and risk rules;
* extraction edge cases: zero-byte, random bytes, truncated, password-protected, image-only, corrupt DOCX, PDF renamed `.docx`, PNG, TXT, a video without an audio stream, and a video **with a silent audio stream** (checks that Whisper does not hallucinate);
* end-to-end CLI runs: report schema with ASCII keys, cross-format exact copy, self-match exclusion, Unicode file names, nested folders, ignored manifest, empty input folder, missing folder exit code, and rejection of misspelled config keys.
